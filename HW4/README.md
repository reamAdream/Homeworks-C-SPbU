# ДЗ4 — параллельное умножение матриц

Умножение плотных матриц на C++17 с использованием `std::thread` и `std::mutex`. Элементы `DenseMatrix` хранятся построчно в одном `std::vector<double>`.

## Реализация

- `Matrix` задаёт общий интерфейс. Метод `mul(const Matrix&, int threadCount)` принимает число потоков и возвращает `std::unique_ptr<Matrix>`.
- `DenseMatrix::mul` динамически распределяет строки результата через общий счётчик `nextRow`. Работник захватывает мьютекс, получает следующую строку и освобождает мьютекс перед вычислениями.
- `mulFrequenceLock` дополнительно захватывает общий мьютекс перед каждым прибавлением к элементу результата. Этот вариант используется для измерения затрат на частую синхронизацию.
- `mulNaive` и `mulOptimize` реализуют последовательное умножение с порядком циклов `i-j-k` и `i-k-j` соответственно.

Работники читают исходные матрицы и записывают разные строки заранее созданного результата. Главный поток запускает работников и дожидается каждого через `join()`. При ошибке создания очередного потока метод дожидается уже запущенных и передаёт исключение вызывающему коду.

Размеры матриц должны быть положительными. Для умножения `A(m×n)` на `B(n×p)` создаётся результат `m×p`. Число потоков должно быть больше нуля. Запрашиваемое число потоков может превышать число логических процессоров.

## Работа с файлами

`DenseMatrix::fromFile(path)` загружает матрицу из текстового файла. Размеры заранее не указываются: число строк определяется по строкам файла, а число столбцов — по количеству чисел в первой строке. Каждая строка должна содержать одинаковое количество чисел. Пустые строки и некорректные значения вызывают исключение.

```text
1 2 3
4 5 6
```

Метод `toFile(path)` сохраняет матрицу в том же формате с перезаписью файла: числа разделяются пробелами, строки — переводом строки. При записи используется `std::numeric_limits<double>::max_digits10`, чтобы сохранить точность значений `double` при последующем чтении.

В папке `data` находятся маленькие входные матрицы `matrix_a_TEST.txt` и `matrix_b_TEST.txt`. Тест сохранения создаёт `example.txt`. Бенчмарк на каждом размере перезаписывает `benchA` и `benchB`, затем загружает их для измерений. После завершения обоих размеров в этих файлах остаются матрицы `1000×1000`.

CMake передаёт путь к папке `data` текущей копии проекта через `HW4_DATA_DIR`. После клонирования проекта путь определяется при настройке сборки.

## Сборка и запуск

Нужны Windows x64, компилятор MSVC с поддержкой C++17, CMake 3.20 или новее, Ninja и компонент C++ AddressSanitizer.

В Visual Studio откройте папку `HW4`. Для тестов выберите `x64-Debug` и цель `test_matrix.exe`, для замеров — `x64-Release` и `bench_matrix.exe`.

Команды ниже выполняются из папки `HW4` в терминале с настроенным окружением MSVC, CMake и Ninja.

Тесты корректности собираются в Debug с `/fsanitize=address`.

```powershell
cmake -S . -B out/build-hw4/x64-Debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build out/build-hw4/x64-Debug --target test_matrix
.\out\build-hw4\x64-Debug\test_matrix.exe
```

Успешный прогон выводит `Success!`.

Бенчмарк собирается отдельной целью в Release с `/O2`.

```powershell
cmake -S . -B out/build-hw4/x64-Release -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build out/build-hw4/x64-Release --target bench_matrix
.\out\build-hw4\x64-Release\bench_matrix.exe
```

## Тесты

В `tests/test_matrix.cpp` результаты обоих параллельных методов сравниваются с `mulOptimize` поэлементно с абсолютным допуском `1e-9`.

| Размер A | Размер B | Потоков |
| --- | --- | ---: |
| 1×1 | 1×1 | 1 |
| 2×3 | 3×5 | 2 |
| 7×4 | 4×2 | 4 |
| 30×30 | 30×30 | 8 |

Случай с семью строками и четырьмя потоками проверяет обработку числа строк, которое не делится на число работников.

Дополнительно проверяются чтение двух матриц из файлов и их параллельное умножение с ожидаемым результатом `[58, 64; 139, 154]`, а также точное восстановление размеров и элементов после сохранения матрицы с дробными и отрицательными числами. Отдельный тест загружает `data/matrix_False_TEST.txt` со строками разной длины и проверяет, что возникает `std::runtime_error`.

## Бенчмарк

`bench/bench_matrix.cpp` создаёт две квадратные матрицы для каждого размера, используя `std::mt19937` с seed `42` и числа из диапазона `[-10, 10]`. Генерация, сохранение и загрузка выполняются до включения таймера. Все варианты для одного размера получают одинаковые входные данные.

Время измеряется через `std::chrono::steady_clock`. В замер входят создание результата, запуск работников, вычисления и ожидание через `join()`.

- `Speedup = T(1) / T(n)` — ускорение относительно отдельного замера `mul` с одним потоком.
- `Efficiency = Speedup / n` — эффективность, где `1` соответствует `100%`.
- `Slowdown = T_frequent(n) / T_mul(n)` — замедление от частых захватов при одинаковом количестве потоков.

### Матрицы 1000×1000

Базовый однопоточный замер составил `414.681` мс.

| Потоков | mul, мс | Ускорение | Эффективность |
| ---: | ---: | ---: | ---: |
| 1 | 412.870 | 1.004 | 1.004 |

| 8 | 74.4481 | 5.570 | 0.696 |

Базовое время измеряется до цикла по потокам, а вариант с одним потоком затем запускается повторно. Поэтому значения ускорения и эффективности в первой строке могут отличаться от единицы. На размере `200×200` разница между отдельными короткими запусками особенно заметна.

На `1000×1000` восемь потоков дали ускорение около `5.57` раза и эффективность около `69.6%`. На `200×200` частые захваты замедлили восьмипоточную версию примерно в `178` раз. Для этого размера внутренний цикл выполняет восемь миллионов захватов дополнительного мьютекса.

Закон Амдала описывает ограничение ускорения последовательной частью работы. В модели `S(p) = 1 / (f + (1 - f) / p)`, где `f` — доля последовательной работы, а `p` — число параллельных исполнителей. В реализации также затрачивается время на запуск потоков, синхронизацию и доступ к общей памяти, поэтому ускорение растёт медленнее количества потоков.

# ДЗ 2 — умножение плотных матриц

Реализация интерфейса `Matrix` и класса `DenseMatrix` на C++17. Матрица хранится в одном `std::vector<double>`: строки расположены последовательно (row-major).

## Реализация

- `mulNaive` использует порядок циклов `i-j-k`.
- `mulOptimize` использует порядок `i-k-j`, сохраняет начала строк и обращается непосредственно к `data_` внутри проверенных границ циклов.
- Виртуальный `Matrix::mul` возвращает `std::unique_ptr<Matrix>`; `DenseMatrix::mul` проверяет тип второго операнда через `dynamic_cast` и вызывает `mulOptimize`.
- В ДЗ2 поддерживается умножение Dense×Dense. Другой тип операнда вызывает `std::invalid_argument`.
- Несовместимые размеры и неположительные размеры матрицы вызывают `std::invalid_argument`. Методы `at` и `set` проверяют индексы и выбрасывают `std::out_of_range` при выходе за границы.

Для A размера m×n и B размера n×p результат имеет размер m×p. Обе реализации выполняют O(m·n·p) арифметических операций. При порядке i-k-j внутренний цикл проходит по соседним элементам строк B и результата.

## Файлы

- `Include/matrix.hpp` — интерфейс Matrix с виртуальным деструктором.
- `Include/dense_matrix.hpp`, `src/dense_matrix.cpp` — DenseMatrix и оба алгоритма.
- `src/main.cpp` — небольшой пример создания матрицы и доступа к элементам.
- `tests/test_matrix.cpp` — тесты корректности.
- `bench/bench_matrix.cpp` — сравнение времени работы.
- `bench/results_release.txt` — сохранённый результат запуска и параметры сборок.

## Сборка и запуск

Проверено на Windows x64 с MSVC из Visual Studio 18 Community. Нужны CMake 3.20 или новее, Ninja и установленный компонент C++ AddressSanitizer.

Следующие команды выполняются из корня репозитория в **x64 Native Tools Command Prompt for Visual Studio** либо другом терминале с настроенным окружением MSVC.

### Корректность: Debug с AddressSanitizer

```powershell
cmake -S HW2 -B HW2/out/build/x64-Debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build HW2/out/build/x64-Debug --target test_matrix
.\HW2\out\build\x64-Debug\test_matrix.exe
```

Ожидаемый вывод: `Success!`. В CMake для этой цели в Debug добавлен `/fsanitize=address`, удалён несовместимый `/RTC1`, а инкрементальная линковка отключена через `/INCREMENTAL:NO`.

Проверяются:

- размеры, начальное заполнение нулями и изменение элемента;
- недопустимые размеры и индексы;
- пример 2×3 на 3×2 с результатом `[58, 64; 139, 154]`;
- вызов умножения через интерфейс Matrix;
- несовместимые размеры для обоих алгоритмов;
- умножение на единичную и нулевую матрицы;
- сравнение алгоритмов на случайных матрицах размеров 1×1 на 1×1, 2×3 на 3×5, 7×4 на 4×2 и 30×30 на 30×30 с абсолютным допуском `1e-9`.

Прямоугольные примеры проверяют, что размеры результата и границы циклов не привязаны к квадратным матрицам. Недопустимые индексы включают отрицательные значения и значения, равные числу строк или столбцов.

### Производительность: Release без санитайзеров

```powershell
cmake -S HW2 -B HW2/out/build/x64-Release -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build HW2/out/build/x64-Release --target bench_matrix
.\HW2\out\build\x64-Release\bench_matrix.exe
```

Также можно открыть папку HW2 в Visual Studio и выбрать конфигурации `x64-Debug` и `x64-Release` из `CMakeSettings.json`, а затем соответствующую запускаемую цель.

## Результаты бенчмарка

Запуск 7 ноября 2026 года на AMD Ryzen 9 8945HX with Radeon Graphics, Windows x64, MSVC, C++17.

В сгенерированном Release-файле `build.ninja` для исходных файлов цели `bench_matrix` проверены флаги:

```text
/DWIN32 /D_WINDOWS /EHsc /O2 /Ob2 /DNDEBUG -std:c++17 -MD
```

Санитайзеры в этой конфигурации не используются. Тесты корректности запускались отдельно в Debug с `/fsanitize=address` и завершились с кодом 0.

| Размер | Наивный, мс | Оптимизированный, мс | Ускорение |
| --- | ---: | ---: | ---: |
| 100×100 | 0.8284 | 0.1713 | 4.84 |
| 200×200 | 6.5873 | 1.1482 | 5.74 |
| 500×500 | 124.1434 | 20.2796 | 6.12 |
| 1000×1000 | 1011.5716 | 168.6525 | 6.00 |

`Speedup = TimeNaive / TimeOptimize`. Это результат одного запуска, а не медиана серии; время зависит от текущей нагрузки и режима работы ноутбука.

Для каждого размера создаются одинаковые входные данные для обоих алгоритмов: `std::mt19937` с seed 42 и числа из диапазона [-10, 10]. Генерация входных матриц, контрольные суммы и вывод находятся вне замеров времени. Создание результирующей матрицы входит во время каждого алгоритма. Оптимизированный алгоритм в текущем бенчмарке запускается первым.

Суммы элементов всех результатов выводятся отдельно для обоих алгоритмов:

```text
Checksum naive:     299037.545733
Checksum optimized: 299037.545733
```

Контрольные суммы обеспечивают использование обоих результатов в бенчмарке. Поэлементная проверка корректности с допуском выполняется отдельно в `tests/`.
